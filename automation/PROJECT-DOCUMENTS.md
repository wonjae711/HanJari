# 기존 프로젝트 문서와 자동화 연결

한자리 「총 정리본」의 「프로젝트 문서」 DB에 있는 기존 7개 페이지를 사용한다. 페이지를 새로 만들지 않는다.

| 페이지 | 반영 내용 |
|---|---|
| 프로젝트 개요 | 목표·확정/제안/제외 범위·사용자 흐름·화면·미정 사항 |
| 개발 방향 기록용 | 사용자 제약·변경 지시, AI의 판단·반영 사유, 검토 결과, 전체 승인 여부 |
| 요구사항 명세서 | 기능·정책·예외·완료 기준과 기능별 인수 기준 |
| 기능별 난이도 및 구현 순서 | 의존 순서·업무 범위·인수 기준. 난이도와 일정은 임의 추정하지 않음 |
| 아키텍처 설계서 | 기술·도메인 상태·정합성·경합·멱등성·운영 정책 |
| ERD | 데이터 모델 절의 테이블·키·제약 초안. 완성된 ERD 다이어그램을 생성했다고 간주하지 않음 |
| API 명세서 | API 계약 절의 경로·입출력·오류 계약 초안 |

자동 반영본은 각 페이지의 `HJ-DOC/v1` 표시가 있는 버전별 접기 영역에 추가된다. 가장 아래의 최신 버전을 연다. 기존 본문과 사람이 남긴 글은 삭제하거나 덮어쓰지 않는다. 사용자 확정과 AI 제안을 구분하고 기획 버전·산출물 번호·독립 검토·전체 승인 여부를 표시한다.

## 상태와 승인

기획 초안은 `초안`으로 표시한다. 전체 기획 승인 후에는 `작성 중`으로 변경하며, 문서 완성이나 구현 완료를 자동 선언하지 않는다. `완료`로 표시한 문서는 새 버전으로 덮지 않고 사용자 확인을 요청한다. 수정 중인 자동 반영본을 발견하면 덮어쓰지 않고 게시를 중단한다.

동시성 비교·카오스·부하 테스트 리포트는 이 기획 동기화의 대상이 아니다. 기획안만으로 실험 결과를 만들거나 상태를 완료로 바꾸지 않는다. 이미 수행한 파일럿 부하 테스트를 이 연결에서 자동 이관하지도 않는다.

## 실행과 재시도

기획·검토·승인 결과를 기록할 때 기존 기록 페이지와 함께 프로젝트 문서를 동기화한다. 지금까지 작성된 최신 기획도 모델 재실행 없이 다음 명령으로 반영한다(저장소 루트 기준).

```powershell
python .\automation\workspace.py sync --project hanjari --activate
```

같은 상태를 재전송하면 이미 존재하는 동일 문서를 대조하며 중복 버전을 추가하지 않는다. 실패 횟수는 문서·내용별로 기록하고 3회 실패 후 사용자 판단을 기다린다. 실패한 경우 로컬 기획·승인 상태는 보존한다. 원인 해결 뒤:

```powershell
python .\automation\workspace.py retry-sync --project hanjari --text "게시 실패 원인과 조치"
python .\automation\workspace.py sync --project hanjari --activate
```

## 기획 입력과 자동 출력의 구분

「프로젝트 개요」는 원본 요구사항으로도 사용한다. `HJ-DOC/v1` 접기 영역은 자동 출력 전용이므로 원본 스냅샷에서 제외한다. 따라서 자동 게시 때문에 승인 해시가 바뀌거나 불필요한 재기획이 발생하지 않는다. 기존 본문·일반 블록의 변경은 계속 감지한다. 요구사항을 바꾸려면 자동 영역 밖의 원본을 수정하고 revise하거나, revise --text로 전달한다.

이 연결은 실행 모델을 추가로 호출하지 않고 반환된 기획 문서의 ## 절을 제목별로 분류한다. 제목에 해당하는 절이 없으면 잘못 추정해 채우지 않는다. 향후 프롬프트의 문서 절 이름을 바꿀 때 project_documents.py 매핑도 검토한다.

대상 페이지 ID·문서명·데이터 소스는 integrations.json의 notion.project_documents에 등록되어 있으며 게시 전에 대조한다. 한자리 전용 매핑은 다른 프로젝트에 상속하지 않는다. 자동화 운영 이력과 프롬프트·명령어 문서는 기존 자동화 기록 공간에서 계속 관리한다.
