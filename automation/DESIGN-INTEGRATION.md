# Claude Design 목업 반영 — 2026-11-02

기준 자료는 저장소 루트 `HanJari app UI mockups`의 `HanJari App.dc.html`, `HanJari 설계 노트.dc.html`, `hanjari-data.js`와 미리보기 이미지다. 원본을 수정하지 않고 네이티브 Tk 화면에 구조·색상·간격·행동 규칙을 옮겼다. 디자인 런타임 support.js, 외부 폰트/CDN, 예시 수치와 시뮬레이션 명령은 실행 코드에 포함하지 않는다.

## 반영 내용

- 5개 메뉴: 진행 현황 / 기획과 결정 / 기능별 업무 / 리뷰와 검증 / 활동·요청·복구. Ctrl+1~5로 전환한다.
- 공통 상단 위치·상태 표시, 아이디어 기록과 Notion 동기화. 사용량과 마지막 갱신 시각은 사이드바 하단에 둔다.
- 진행 현황의 상태·다음 행동·담당 카드, 9단계 흐름, 최근 검토·주의 항목·활동 카드.
- 기획 화면의 목차·문서·승인 패널, 검색 결과 수와 다음 찾기, 해시 펼쳐 보기. 폭 1200 미만에서는 목차를 접고 본문과 결정 패널을 유지한다. 패널 경계는 드래그로 조절할 수 있다.
- 검토 중 새 기획이 도착하면 기존 문서를 고정하고 승인 차단. 최신 버전을 명시적으로 열면 읽음 확인을 초기화한다. 최종 승인에는 기존 정확한 해시 검사를 그대로 적용한다.
- 기능 검색·상태 필터와 목록/상세 분할, 코드 리뷰의 검증/독립 리뷰/사용자 수락 구분과 관련 파일 목록.
- 통합 활동 화면의 기록·요청·복구 보기. 반복 방지와 전송 실패 횟수는 저장된 기록만 사용한다. 실제 복구 대상과 원인 해결 확인이 있어야 복구 버튼이 활성화된다.
- Windows 제목 표시줄의 어두운 테마와 기존 둥근 카드·버튼 유지.

## 실제 데이터와 한계

기획은 프로젝트 상태의 현재 리비전, 검토는 해당 실행에 저장된 근거를 사용한다. Notion 표시는 로컬 전송 기록 요약이며 실시간 외부 연결 확인 결과가 아니다. UI 조회는 모델·Notion 호출을 하지 않는다. Claude 사용량이 오래됐거나 기준에 도달하면 Claude 개발 시작 버튼을 막으며 Codex 기획/검토에 해당 사용량 제한을 잘못 적용하지 않는다. 실행 시 제어기가 다시 검사한다.

목업의 결정 선택지 라디오, 버전 간 의미 기반 diff, 파일별 읽음 영구 저장, 편집기 열기, 기준별 근거 매핑, 기능별 수정 요청 전용 명령은 이번 범위에서 새로 만들지 않았다. 미결정 사항은 실제 질문으로 표시하고 기존 수정 요청으로 전달한다. 파일은 저장된 목록과 근거를 표시하며 승인 해시·프로젝트 ID·Notion 연결을 변경하지 않는다. 예시 프로젝트·프롬프트·시간·토큰 수·테스트 통과 수치를 실제값처럼 채우지 않는다.

구현: `studio_view.py`가 `desktop.py`의 네이티브 컨트롤·작업 요청·승인·종료 보호를 재사용한다. `dashboard.py`는 기존 상태 조회에 사용자 확정 제약과 AI 판단·제안을 추가 제공한다. 바탕화면 바로가기와 실행 명령 `python automation/desktop.py`는 그대로다.

검증: 134개 회귀 테스트. 새 테스트는 승인 전 읽음 확인, 검토 중 버전 변경, 복구 확인, 실제 사용량 기준, 읽기 전용 화면 전환과 검색을 검증한다. 실제 기획 승인이나 모델 실행은 수행하지 않는다.
