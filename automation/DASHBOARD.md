# 로컬 GUI 대시보드

기존 workspace.py 위에 Python 표준 라이브러리 HTTP 서버와 HTML/CSS/JavaScript 화면을 연결한다. 별도 패키지 설치나 프론트엔드 빌드가 필요 없다. Windows 현재 사용자 환경에서 실행한다.

## 시작

```powershell
cd C:\Users\dnjsw\projects\HanJari
python .\automation\dashboard.py
```

브라우저에서 http://127.0.0.1:8765 에 접속한다. 서버를 켜거나 화면을 여는 것만으로 AI를 실행하지 않는다. CLI에서 준비한 환경변수(DB 등)는 이 터미널에도 설정되어 있어야 한다. 비밀번호는 대시보드에 입력하지 않는다. 포트가 이미 사용 중이면 `--port 8766`을 사용한다.

1. 프로젝트 선택 후 현재 단계, 기획안, 검토 의견을 확인한다.
2. 기획 승인 버튼에서 전체 기획안을 읽고 확인란을 선택한다. 화면에 표시됐던 해시로만 승인 요청한다. 승인 처리 완료와 개발 시작은 별개다.
3. 자동화 실행 버튼을 누르면 기존 수동 활성화 흐름을 한 번 실행한다. Claude 사용량 제한, 반복 방지, Git/DB 확인, 사용자 승인 경계는 기존 CLI가 적용한다.
4. 실행 중 중단 요청은 현재 단계 완료 후 다음 작업을 막는다. 아이디어 기록은 즉시 요구사항을 바꾸지 않는다. 작업이 멈춘 뒤 수정 요청으로 새 기획 버전을 만든다.
5. 기능 검증 후 관련 파일·근거를 확인하고 현재 기능 리뷰 완료를 기록한다. PR을 자동 병합하지 않는다.

화면은 3초마다 로컬 상태 파일을 조회한다. 이 조회는 모델이나 Notion API를 호출하지 않는다. 사용량은 usage.json에 저장된 값과 갱신 시각이며, 오래된 값은 갱신 필요로 표시한다. 새 프로젝트 등록은 기존 workspace.py register 명령을 사용하고 화면을 새로고침한다.

## 운영과 한계

- 현재 PC의 `127.0.0.1`에서만 접속한다. 공용 네트워크에 공개하거나 포트 전달하지 않는다. 외부 호스트·Origin·교차 사이트 요청을 거부하고 변경 요청에 임시 세션 토큰을 요구한다.
- 명령은 허용 목록의 workspace.py 동작으로 제한한다. 사용자 입력은 셸로 평가하지 않는다. 상태 데이터는 HTML로 실행하지 않고 텍스트로 표시한다.
- 일반 요청은 한 번에 하나만 실행한다. 실행 중에도 중단 요청과 아이디어 기록은 별도로 허용한다. 다른 터미널에서의 중복 실행은 기존 CLI 잠금이 추가로 차단한다.
- 실행 기록은 Git에서 제외된 automation/.runtime-dashboard/*.log에 저장한다. GUI에는 원시 로그·인증 설정을 전송하지 않는다. 오류가 발생하면 화면에 나온 로컬 로그 경로를 확인한다.
- 요청 처리 이력은 서버 메모리에 있다. 재시작하면 이 목록은 초기화되지만 실제 기획·개발 상태와 활동 기록은 기존 파일에 남는다.
- **실행 중 서버 터미널을 닫지 않는다.** Ctrl+C는 대시보드 서버를 종료하며 이미 시작된 자식 작업의 강제 종료를 보장하지 않는다. 먼저 중단 요청 후 현재 단계와 요청 처리가 완료된 것을 확인한다.
- 최종 부하 테스트는 기존처럼 사용자가 직접 수행한다. 이 GUI는 별도의 상시 실행 스케줄러가 아니다.

검증: `python -m unittest discover -s automation -p "test*.py"`. GUI/HTTP 테스트는 에이전트를 실행하거나 실제 기획을 승인하지 않는다. `--mode mock`은 별도 모의 상태를 사용하며 실제 승인·개발과 섞지 않는다.
